# V3.1 to V4 migration

V4 preserves minimal cognitive composition and adds a context/memory
lifecycle around it. Migration is read-only until a separate memory-change
proposal is explicitly authorized.

## Compatibility

- V3.0 task packets remain valid through `method_packs` and `domain_packs`
  aliases and emit a legacy warning.
- V3.1 task packets and requests remain readable. A V3.1 request is normalized
  into a V4 context plan and emits a V4 task packet with a warning.
- V4 never emits V3 or V3.1 artifacts.

## State mapping

| V3/V3.1 field | V4 destination | Rule |
| --- | --- | --- |
| `accepted_decisions` | `corporate_memory.decision_log` | Preserve acceptance evidence; otherwise propose backlog review. |
| `evidence_register` | `corporate_memory.context` | Preserve provenance and epistemic class. |
| `open_questions` | `corporate_memory.backlog` | Preserve owner; add status and next gate during migration review. |
| `risk_register` | `governance.risk_register` | Preserve without reclassification. |
| `authority_grants` | `governance.authority_grants` | Preserve scope, expiry, and revocation. |
| `learning_events` | `governance.learning_events` | Preserve source task and limitations. |
| `composition_observations` | `governance.composition_observations` | Never update routing automatically. |
| `routing_policy_*` | `governance.routing_policy_*` | Preserve version and `auto_update: false`. |

Working memory starts empty. No legacy field is silently classified as working
memory. Migration normalization never writes files, changes routing policy, or
creates authorization.

Run the read-only normalizer with:

```text
python scripts/control_plane.py migrate-state --state path/to/v3-project-state.json
```
